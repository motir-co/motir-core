# The permission-gating inventory — every authed page and every control that writes

**Story:** [MOTIR-6166](motir:cmuevm0tl0070hztxuijzdjra) · **Subtask:** MOTIR-6172 · **Measured on:** `origin/main` @ `fde48204f` (2026-09-25)

This is a snapshot: a list of what the app offered each actor on the day it was taken. It is **not** a
specification. The rule it measures against is the one in
[`design/projects/design-notes.md`](../../design/projects/design-notes.md) § _Amendment 2026-08-08 —
hide the entry point, disable the in-place control, guard the destination_:

1. **HIDE an entry point** whose destination the actor cannot use: a nav row, a settings door, a
   ⌘K action, a menu row, an add-link button.
2. **DISABLE, with a reason, an in-place control** on a surface the actor can see: a field picker, a
   toggle, the Create button.
3. **GUARD every door on the server.** Hiding is presentation and never enforcement.

The rows here were produced by reading, and then confirmed where it mattered:

- by a **reproduction on real Postgres** for every server-side hole (the four bugs below);
- by a **browser walk as a project Viewer and a Member** for the item page, the list, the board and
  the backlog (§ _The Viewer walk_).

## How to read a row

| Column          | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Service key** | The permission key (or role check) the SERVICE behind the control asserts, read from the service, never from the UI. `ungated` means nothing is asserted beyond the tenant.                                                                                                                                                                                                                                                                                                         |
| **UI key**      | What the control consults before it renders or enables itself. `none` means it renders for everyone.                                                                                                                                                                                                                                                                                                                                                                                |
| **Treatment**   | What the rule says the control should do for an actor without the key: `HIDE` (entry point), `DISABLE` (in-place control, with its reason), or `N/A` (a read, or a write on your own things).                                                                                                                                                                                                                                                                                       |
| **Status**      | `CORRECT` — the UI consults the same key the service asserts, and draws the rule's treatment. `GAP` — it does not. `BUG` — the SERVER is missing its guard (the rule's part 3), filed as a bug. `HANDED` — the row belongs to another card, named. `NEEDS DESIGN` — no row of the treatment table covers this surface. `FIXED` — a GAP this story closed, with its pull request. `JUDGED-CORRECT` — a row first read as a GAP and found correct on closer reading, with the reason. |
| **Owner**       | The card that fixes the row.                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

Row ids are stable within this document: `A` is the item-page action files, `B` the collection and
app-level actions, `C` the settings and account actions, `D` the pages and navigation entries.

**Coverage:** every `page.tsx` under `app/(authed)` has exactly one `(page)` row in section D. Every
function exported from a `'use server'` file under `app/(authed)` has at least one row in A, B or C
(one row per caller where callers differ). The recount script at the end reproduces both totals
from the ref.

## The Viewer walk — what a project Viewer is actually offered (2026-09-25)

**Setup.** A production build of `origin/main` @ `fde48204f` in headless Chromium, seeded with the
shipped `tests/e2e/_helpers/permission-gated-ui-seed.ts`. The actor is a plain workspace member on
the built-in project **viewer** role, so the workspace owner's always-pass rail cannot hide anything.
The walk collected every VISIBLE, ENABLED button on each surface, then clicked each `Edit <field>`
chevron on the work item page and counted what opened.

**Work item page.** The rail offers enabled chevrons for Status, Type, Work type, Priority, Assignee,
Parent, Due date, Sprint and Estimate. Clicking them gave:

| Chevron                               | What opened for the Viewer                                        |
| ------------------------------------- | ----------------------------------------------------------------- |
| **Work type**                         | a listbox with **15 enabled options** — the MOTIR-4822 path, live |
| **Sprint**                            | a listbox with **1 enabled option**                               |
| **Due date**                          | the calendar (2 popovers)                                         |
| Status · Priority · Parent · Estimate | a disabled control, with nothing saying why                       |

This confirms rows A26 and A27, and the no-reason rows (A25, A35). The Watch toggle and the ⋯ menu
are enabled, and both are correct: watching is a self-only act, and the menu hides the rows the
actor lacks.

**Items list.** No write control is enabled. Filters, view and sort only.

**Board.**

- The Group-by segmented control (**None / Assignee / Epic / Priority**) and **every column's actions
  menu** are enabled. This confirms B39 and B40.
- The read-only banner's status region reads **`boards.readOnlyBoardBanner`**: the untranslated
  i18n key, shown to every Viewer. That is row B55, found only by the walk.

**Backlog.** **Create sprint**, the row **Work item actions** menu and the inline **Create work
item** row are all enabled. This confirms B49, B50 and B51.

**Rail.** Workbench, Work Items, Ready, Runs, Boards, Roadmap, Backlog, Dashboard, Reports, Approval
records, Codebase. No settings door, which is correct: every settings room is closed to a Viewer.
"Approval records" and "Runs" are the rooms story's (D89, D90). The org-menu gaps (D38–D42, D80)
belong to the org tier, which this walk's actor did not open.

**Not observed:** the Member half of the walk did not complete (the script's chevron loop outlived
its timeout once a Member's opened editors replaced the chevrons), so "a Member keeps everything"
is not claimed here. It is the story E2E's own case (MOTIR-6178).

## Recount — the populations, from the ref

Both totals are taken from a REF, never a working tree. The export pattern is anchored at the line
start because every `'use server'` file here declares its exports that way. The check below also
confirms that no file carries a `'use server'` directive anywhere but its first line, which is the
case a line pattern could miss.

```sh
REF=origin/main
# pages under app/(authed)
git ls-tree -r --name-only "$REF" 'app/(authed)' | grep -c '/page\.tsx$'                 # 71
# 'use server' files, and proof there is no inline directive the file-level grep would miss
git grep -l -E "^['\"]use server['\"]" "$REF" -- 'app/(authed)' | wc -l                   # 26
git grep -n -E "['\"]use server['\"]" "$REF" -- 'app/(authed)' | grep -vc ':1:'           # 0
# exported functions in them (types and interfaces excluded)
for f in $(git grep -l -E "^['\"]use server['\"]" "$REF" -- 'app/(authed)' | sed "s#^$REF:##"); do
  git show "$REF:$f" | grep -cE '^export (async function|function|const|let) '
done | paste -sd+ | bc                                                                    # 92
```

Rows by section: **A** covers the 36 exports of the nine `items/[key]` action files, **B** the 25
exports of the six app-level files (plus 17 write controls that call a route rather than an action),
and **C** the 31 exports of the eleven settings files, for a total of 36 + 25 + 31 = **92**. **D**
holds the 71 pages plus 20 navigation entries.
