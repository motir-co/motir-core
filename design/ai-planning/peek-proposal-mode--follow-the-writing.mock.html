MOTIR-11249 · “Follow the writing” — a control in the proposal quick view of a card being written (delta on peek-proposal-mode--being-written, Part XXIX §29.5 / P4)

F0 · the access path — the card being written on the overlay canvas opens the proposal quick view, and the control is in its header from the first frame

F1 · writing, NOT following (the default on every open) — the control is offered; the view does not move as text grows (the caret is below the fold)

F1b · the control’s tooltip and focus ring — hover or keyboard focus, both themes, en and zh

F2 · FOLLOWING — pressed; the caret is brought into view after every read (here in the description)

F3 · FOLLOWING, the caret moves to another field — the explanation grew last, so the view follows the caret there, not to the bottom of the column

F4 · FOLLOWING, then the reader scrolls (wheel, touch, scroll key, scrollbar drag) — following turns off at once, the view stays where the reader put it, the control returns to its offer

F5 · writing ENDS while following — the stored card lands (written): the control and the cue’s visible line go, the view does not jump

F6 · writing ENDS while following — the draft goes with no write (idle): the control goes with the partial text, nothing is announced

F7 · a card NOT being written — a stored proposal on the generating overlay, and the plan page’s peek (P9): no control, ever

F8 · prefers-reduced-motion: reduce — following looks the same; every follow scroll is instant (behavior "auto"), in both motion modes after the first press

F9 · how the reader’s scroll is told from the follow’s own scroll, and the keyboard

Following is turned off by the reader’s intent to scroll, read from the input events that cause a scroll — never from the scroll event, which the follow’s own scrollTop write and the browser’s scroll anchoring fire as well. So the follow can never turn itself off, and no timing window or “programmatic” flag is needed.
Input inside the quick view’s main columnWhile following
wheel (mouse wheel, trackpad)turns following OFF before the column moves
touchstart / touchmove (finger drag)turns following OFF
pointerdown on the column’s own scrollbar (target is the scroller itself)turns following OFF
keydown of a scroll key with focus in the column: ↑ ↓ PageUp PageDown Home End Space Shift+Spaceturns following OFF
the follow’s own scrollTop write, and the browser’s scroll anchoringnever turns it off — no scroll event is read at all
Tab / Shift+Tab to the control, then Enter or Spacetoggles following on / off (a native button)
Esccloses the quick view (shipped); reopening starts not following
