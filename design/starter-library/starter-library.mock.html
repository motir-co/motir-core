Operator console — Starters

MOTIR-705 · story MOTIR-704. A new page in the shipped operator console: the starter library every repository Motir creates starts from. Each entry shows its role and stack, the uses, sizes and hosting targets it serves, whether it is active or retired, and where it came from. Filters for role, status and hosting target live in the URL. Promoting and retiring are drawn in starter-library--promote.mock.html.

Operators and superadmins only. The Starters row appears in the rail for them; for support it is absent and /admin/starters answers 404, as Fleet settings and Audit log do. Nothing on this page changes a repository that already exists.

Panel 1 · The library, populated — the door is the new Starters row in the rail’s Operations group, after Ideas. Status defaults to Active.

Seven active starters: Motir’s own six (decision MOTIR-706 v2) and one an operator promoted. A starter that no Motir hosting target deploys reads Not deployed by Motir hosting. A role’s default carries a Default pill and no Retire action. 25 starters to a page.

Panel 2 · Filtered by hosting target — the target filter open, then Fly applied

The target filter offers the closed list of hosting targets plus Not deployed by Motir hosting, which finds the starters with no target. The URL becomes /admin/starters?target=fly. Only the library card is drawn; the shell is Panel 1’s.

Panel 3 · Retired — the Retired filter, and an entry shown distinctly

A retired starter stays in the library as a record. Its row is quieted (--el-surface-soft), its status pill is grey, it has no action, and its provenance adds who retired it, when and why. Matching never picks it and the room’s picker never offers it.
