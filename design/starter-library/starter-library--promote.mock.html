Operator console — promote and retire a starter

MOTIR-705 · story MOTIR-704. Promote a repository on the Starters page opens a form at /admin/starters/promote: pick a repository Motir created and a ref, say what the starter is, and choose its uses, sizes and hosting targets explicitly — nothing is ticked for you. A required reason, then a confirm. Every refusal the route returns is drawn, each naming the file, field or target at fault.

Retire asks for a reason in a confirm. A role’s default cannot be retired. Both actions are an operator’s, never automatic, and each writes a row to the audit log. Support never sees either.

Panel 1 · The promote form, filled — in the console shell, Starters active

Every field is required except the hosting targets, which may be left empty for a starter Motir hosting does not deploy. Review promotion stays disabled until the required fields are filled and at least one use and one size are ticked.

Panel 2 · Starting blank — nothing is ticked, and the source picker open

No use, size or hosting target is pre-ticked, even when the source repository has them set: what a starter serves is the operator’s claim, not an inference. The picker lists only repositories Motir created; a customer’s own repository is never listed. One that is not created yet, or is being handed to its owner, is listed but cannot be picked, and says why.

Panel 4 · The source is refused — the alert sits at the top of the form, which keeps everything typed

The picker already keeps most of these out, so each is the server’s answer when the repository changed after the form loaded. The alert names the rule; the form stays filled so the operator can pick another repository or ref and confirm again.

Panel 5 · The hosting manifest refuses — read only when a hosting target is ticked

A claimed hosting target must be one the repository’s motir.hosting.json declares at the ref. Each alert names the file, and the field or target at fault; an undeclared target also marks its checkbox group.

Panel 6 · Field refusals — a value outside its list, a key in use, a copy that would overwrite

Each refusal sits under the field it names. A value outside a closed list can only arrive when the lists changed after the form loaded; the error names the values that are allowed.

Panel 7 · Retire — the confirm asks for a reason; then a role’s default refused

Retire on a library row opens this confirm. The button stays disabled until a reason is typed. A role’s default shows no Retire action on its row; if one is retired anyway (the defaults changed after the page loaded), the confirm shows the refusal and keeps the starter active.

Panel 8 · Done — back on the library, the toast says what changed

After a promote the library opens with the new starter first and briefly tinted; after a retire the row leaves the Active filter. Each toast says what changed for new repositories, which is the only thing either action changes.
