The preview gate — what a person meets between a preview link and the preview

Story MOTIR-5766 · card MOTIR-5774. Two pages on app.motir.co (sign in, refused) wear the shipped (auth) frame. Five on the preview host (building, starting, failed, closed, not found) wear a minimal Motir frame that cannot be mistaken for the tenant's application. Every value of the state enum building · starting · ready · failed · closed resolves to a panel below; ready has no page, because it is the application.

E · The entry — from the Development block to the preview
The door is the In the preview fact of the Development block (../github/design-notes.md §20, Panel 12e), composed and not redrawn: its pill already reads Ready, Deploying, Deploy failed or Inactive from the GitHub deployment state the lifecycle posts. Without a gate cookie the preview host always sends the viewer to app.motir.co/preview-access, whatever the host holds — so the host never says whether a preview exists before the gate has decided who is asking.
In the preview · Ready pr-14--portal.preview… → Preview host, no cookie 302 → preview-access → app.motir.co/preview-access ?host=…&return=/ → Signed out? the shipped sign-in, Panel 1 → Member: token, 60 s /__motir/preview-auth → The preview __Host-motir-gate, 8 h
1 · Sign in to view — signed out, on app.motir.co
The shipped sign-in card, unchanged, with ONE banner above it. The banner names only the address, which is already in the viewer's address bar; it names no project, repository or organisation, because a signed-out viewer may have no right to know them. After sign-in the viewer returns to preview-access with the same host and return.

2 · A member — no page at all
A viewer who holds project:browse on the repository's project sees nothing on app.motir.co: preview-access mints the single-use token and redirects in the same response. Drawn as the path, because there is no screen to draw. The preview host consumes the token, sets the host-only gate cookie, and redirects to the remembered path — then serves the application if the row is ready, or Panels 4 to 8 if it is not.

3 · Refused — signed in, without project:browse
Says plainly that this account cannot open it, and offers the two ways out that exist: go to Motir, or sign in as someone else. It names NO project: the same page answers a host that matches no preview, so a viewer without access learns nothing about what exists. The account shown is the viewer's own email. There is no access-request flow in Motir today, so the copy points at the person who shared the link rather than at a button that does not exist.

6b · Not available in previews — the gate's 501, 413 and 411
MOTIR-5769 §5: the gate refuses rather than truncates. A websocket upgrade gets 501, a body over the target's gated limit 413, a write with no Content-Length 411. A browser that navigates into one sees this card in the Failed frame, neutral rather than red because the preview is fine; a script gets the status and the same sentence as plain text.
