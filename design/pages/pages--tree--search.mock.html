Pages — search from the page tree

One Search box above the tree finds a page by a word in its title or text, or by what it is about. While a query is active a result list replaces the tree; clearing the box brings the tree back. A reader without page:view never reaches this page: /pages answers its existing 404, so no in-page no-access state is drawn.

1THE ACCESS PATH AND IDLE — Pages in the rail opens /pages; the Search box sits under the header, above the unchanged tree.

Door: the shipped Pages rail row opens /pages. The Search box is the first thing in the page body, under the header (title, subtitle, Archived pages, New folder, New page) and above the tree. The tree’s rows are the approved tree mock’s and are not redrawn here beyond a few for context.

Idle: an empty box with its placeholder. The mode is never a choice: there is no full-text / meaning toggle, and the placeholder says the box finds a page either way.

2FOCUSED, AND AN EMPTY OR WHITESPACE QUERY — the Empty hint under the box; the tree stays.

Focused: the input’s focus ring (--focus-ring-color). While the box holds focus and its query is empty or only spaces, the Empty hint shows under it. Nothing is requested, there is no Pending indicator, and the tree stays: a blank query never lists every page.

The right board is a query of three spaces: the same frame. The Clear control appears once the box holds any character, spaces included, so the member can empty it.

3LOADING — the Pending indicator while a settled query is in flight.

First search: the Pending indicator (a spinner in the box, before Clear, announced once as “Searching…”) and three row-shaped blocks where the list will be. The tree is gone as soon as the query settles.

A later search: the previous hits stay on screen, unchanged and still clickable, until the new answer replaces them; only the indicator in the box says a search is running. An older answer never overwrites a newer one.

4RESULTS — the Hit row in its three snippet cases, and Load more.

Hit row: the page glyph, the Hit title, the Hit place and the Hit snippet; the whole row is one link to /pages/{id}. Hovered: --el-surface. Rank is never shown; the list is in the service’s order.

Hit place is the place the Link page picker and the Pages section already draw: the root crumb (Pages), then each folder with its folder glyph, then the parent page; a top-level page at the root shows the root crumb alone. Past five segments it folds the middle to “…”, as the shipped place does.

Hit snippet is the service’s plain text, two lines at most. Word match: each query word found in it is emphasised in the browser, by weight and a yellow tint, never by colour alone. Found by meaning only: the snippet is the body’s opening words and nothing is emphasised. Empty body: no snippet line; the row is title and place.

Load more closes the list when the answer carries a next page. Page titles and snippets are page content and are never translated; the zh board shows them as written.

5LOAD MORE IN FLIGHT, AND THE END OF THE LIST.

In flight: the Load more band becomes “Loading…” with the spinner; the hits above stay where they are, and the next ones append below them. A failed next page shows the Error state’s sentence and Retry in this band, retrying the same page.

End: an answer with no next page has no band at all. Nothing says how many hits there are: the search is keyset-paged and knows no total.

6QUERY TOO LONG — the Too-long hint, inline, naming the 200-character limit.

A query over 200 characters (after trimming) is not sent. The Too-long hint appears under the box in the box’s own helper line, with the info glyph: it is a hint, not an error screen, so there is no danger colour and no alert. Whatever was below the box stays: the tree, or the previous list as here. Shortening the query to 200 or fewer removes the hint and searches.

7NO RESULTS — the No-results message names the query, with its clear control.

A settled answer with no hits shows the No-results message in the list’s place, naming the query as typed, with Clear search, which empties the box and brings the tree back. It is not Loading (no indicator is running) and not an error (the search answered).

8DEGRADED — the Degraded note, for full-text only and for not indexed.

When meaning search did not take part, the hits are still listed and the Degraded note sits above them: one line, the info glyph, the informational sky tint with --el-text-strong ink. It is never an error colour, an error icon, a toast or a modal: the member’s search worked, in a lesser mode. The copy is the app’s own, keyed by the answer’s mode; the service’s English message is not shown.

Full-text only: meaning search did not run for this query. Not indexed: the project’s pages are not indexed for meaning yet. A not-indexed answer with no hits shows the No-results message under the note.

9ERROR — a failed search, with Retry.

A request that fails for any reason other than a named refusal shows the Error state in the list area: the tree’s own failed-read treatment (the alert glyph, one sentence, a secondary Try again), so a failed search looks like a failed tree read. Retry repeats the same query. The header and the Search box stay usable; editing the query also searches again. Distinct from No results (which answered) and from Loading (which is still waiting).

10KEYBOARD — the focus order, with the focus ring on each stop.

Order: the Search box (1) → each hit, top to bottom (2, 3, 4) → Load more (5). The numbered chips are review annotation only. Each stop draws the focus ring: the box’s outer ring, the hit row’s inset ring (as the tree’s rows draw theirs), Load more’s outer ring.

Keys: Down from the box moves to the first hit; Up and Down move between hits; Up from the first hit returns to the box; Enter opens the focused hit; Tab and Shift+Tab walk the same order; Escape in the box, or the Clear control, empties the query and brings the tree back, and Escape on a hit returns focus to the box.
