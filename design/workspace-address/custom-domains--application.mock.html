Custom domains — the application a domain serves

A customer domain names exactly one of the workspace's hosted applications, or none yet. The owner chooses it when adding the domain and can change it on the domain's row; the row is the one place the choice is read back. Scenario: the Acme workspace, which hosts Shop (shop) and Docs (docs). Every panel not drawn here stands as custom-domains.mock.html draws it.

Panel A — the Add-domain dialog · amends panel 5 · no application, one, several

The dialog gains its second field, the application picker, under the domain. With no hosted application there is nothing to pick, so a settled line stands in its place and Add domain stays enabled. With exactly one, it is preselected. With several, nothing is preselected and No application yet is an explicit choice. The five refusals of panel 5 are unchanged and sit under the Domain field as drawn there.

Panel B — the domain row · amends panel 8 · bound, unbound, no longer listed

The Application line names the chosen application, with its slug beside it. Unbound, it says the domain names no application and serves nothing yet, and promises nothing more: the Application control beside it is how the owner fixes it. A row naming an application that is no longer listed says so, and never falls back to the unbound words. The certificate line and the actions of panel 8 are unchanged.

Panel C — the Application control, open · on a bound, an unbound and a no-longer-listed row

The same picker as the Add-domain dialog, in a Modal titled for the domain. The application the domain names now is preselected and ticked; Save stays disabled until the selection differs from it. A no-longer-listed application is not an option, so nothing is preselected and any choice is a change.

Panel D — the change · confirm, saving, failed

Once the selection differs, the Modal states what the save changes and what it does not, and Save is enabled. Saving: Save shows its spinner and both buttons are disabled; the row is unchanged until the write answers. Failed: the message sits above the footer, Save reads Retry, and the row still names the application it named before.

Panel F — the apex records · replaces panel 6's apex half · the edge's own addresses

A root domain points its A and AAAA records at the addresses motir-edge holds for customer domains — Motir's own, not an address other sites use. The values are configuration and are drawn here as what they are. When an address list is not configured its row is absent, never blank or invented, and the ownership TXT still shows. The subdomain half of panel 6 (one CNAME and the TXT, no note) is unchanged.

acme.com Unverified

Create these 3 records at your DNS provider, then check.

Type Name Value
A @ the edge's IPv4 address
AAAA @ the edge's IPv6 address
TXT _motir-verify motir-verify-k7P…2cB

A root domain cannot take a CNAME, so it points at Motir's own addresses, which motir-edge holds for customer domains. If they ever change we will tell you before they do.
