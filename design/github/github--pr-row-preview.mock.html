The preview on a pull request’s row

AMENDS design-notes.md § 19 (the Development row) and § 25 (a pull request’s facts live on its row) — MOTIR-10097, 2026-10-30. Spec: § 31. Where it lives: the item page → Development card and the quick-view peek’s Development section, reached from any board card, list row or Workbench row that opens an item. No new entry point, no new section. A pull request on a repository Motir hosts gains ONE element: a third line in the row’s text column, under owner/name · #n, saying what its preview is doing and, when it is live, linking to it. Nothing else on the row moves. Fixture: the story ACME-12, its pull request moooon/motir-core · #31, whose preview host is pr-31--motir-core.preview.motir.site.

Absent (P6) is the rule most worth reading. A connected repository, a repository whose previews are off, a pull request that never built, and an item with no pull request draw nothing: no label, no placeholder, no dashed outline, no muted “No preview”. The row is byte-identical to the shipped row, as ci: null draws no CI pill. No loading, error or refresh state of its own: the rows are server-rendered, and a state change arrives through the block’s one router.refresh().
